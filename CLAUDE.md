# CLAUDE.md: Atlas of Motion

Browser-based 3D atlas of the human muscular system plus a strength-exercise database, exercise comparison and a weekly workout planner. Static site, no backend, no build framework. Target deployment: GitHub Pages.

## Golden rules

- **`index.html` is generated.** Never hand-edit it. Edit `tools/template.html` (UI/JS/CSS) or the data sources in `tools/`, then run the pipeline (see below) to regenerate it.
- `index.html` (~250 kB) embeds only the metadata (`META`, ~230 kB of JSON); the geometry lives in `geo/{low,medium,high}.bin` and is fetched at runtime (so the app must be served over http(s); `file://` shows an error in `#loadMsg`). Avoid printing `index.html` whole; grep or read `tools/template.html` instead.
- Anatomy keys are lower-case English names from the source data (e.g. `"gluteus medius"`, `"pectoralis major"`). Every exercise target must reference an existing key (and, if given, an existing part). `tools/exercises.py` asserts this; keep the asserts.
- After any change: rebuild, run `python lint.py` (in `tools/`), then run the smoke test (`tools/test`). Commit the regenerated `index.html` together with its sources, or CI fails.

## Build pipeline

Run from `tools/` (scripts use relative paths):

```bash
cd tools
git clone --depth 1 https://github.com/JohanBellander/BodyExplorer.git   # source GLBs, ~60 MB
pip install trimesh pyfqmr numpy
python build.py             # three levels -> ../geo/{low,medium,high}.bin + meshes.json (committed outputs)
python meta.py              # reads meshes.json -> meta2.json
python exercises.py         # -> meta3.json
python lint.py              # data checks
python assemble.py          # -> ../index.html and ../sw.js
cd test && npm install && npm test
```

If you only changed `template.html`, `data/*.txt`, `bones.py`, `exercises.py` or the mapping in `meta.py`, skip `build.py` and run `python meta.py && python exercises.py && python lint.py && python assemble.py` (no BodyExplorer clone needed: `meshes.json` and `geo/*.bin` are committed). `build.py`, `meta.py`, `exercises.py` and `assemble.py` are deterministic, so regenerating without edits reproduces `index.html` and `sw.js` byte for byte (CI relies on this); `build.py` gzips with `mtime=0` for the same reason. Rerun everything after changing `LODS` in `build.py`.

### Source data

- `BodyExplorer/public/anatomy.glb`: 467 muscle/tendon meshes (401 BodyParts3D + 66 Z-Anatomy), already aligned. Names like `"acromial part of left deltoid"`.
- `BodyExplorer/public/skeleton.glb`: 201 bone meshes. No sacrum, coccyx or costal cartilages.
- Source coordinates: millimetres, X = subject's left (+), Y = posterior (+, so the front is -Y), Z = up.

### build.py

- Builds all levels in one run from the `LODS` table `{level: (muscle ratio, bone ratio, face floor, preserve_border)}`: **low** 0.16/0.12 (~362k triangles, 2.3 MB), **medium** 0.45/0.35 (769k, 5.2 MB; the original setting), **high** untouched source (1.59M, 9.9 MB). Each mesh is decimated with pyfqmr to `max(min(faces,floor), faces*ratio)`. Low needs `preserve_border=False` (with it pyfqmr stalls near 600k faces because the meshes have many open borders); because that can erode thin open meshes, `simplify()` redoes a mesh with borders kept when its bbox diagonal shrinks >7% or its area >20%. All levels have the identical mesh list/order (asserted).
- Transforms to scene space in metres: `x = X`, `y = Z` (up), `z = -Y` (front faces +z). Shifts so x/z are centred and the feet sit at y = 0 (shift taken from the undecimated set, applied to all levels). Height ≈ 1.71.
- Reorders vertices by first use, quantises positions to uint16 over one global bbox shared by all levels (`lo`, `span` in meshes.json = union over the levels).
- `../geo/<level>.bin` layout (all little-endian uint16, gzip-compressed, no base64), per mesh in meshes.json order: x-plane[nv], y-plane[nv], z-plane[nv], then indices[nf*3]. Each stream is delta-coded (wrap-around mod 65536) and zigzag-encoded. Decoder: `prev = (prev + ((z>>>1) ^ -(z&1))) & 0xFFFF`. Max 65535 vertices per mesh and level (asserted). The per-mesh vertex/face counts are in `meshes.json` (`lod[level].counts`) and are the only thing the decoder needs.

### meta.py

- Canonicalises names: strips left/right (stored as side `"L"`/`"R"`), `(2)` suffixes, `" of hand"`/`" of foot"` → `" (hand)"`/`" (foot)"`.
- Derives the info **key** by stripping part/head prefixes (`PARTPRE`, `HEADPRE`, e.g. `"acromial part of deltoid"` → key `"deltoid"`, part `"acromial part"`) and merging series via `MERGE` (lumbricals, multifidus, iliocostalis, levator ani parts, thoracolumbar fascia layers, ...).
- Reads `meshes.json`; emits META mesh rows as `[kind,key,side,part]` (no counts) and passes `lo`, `span`, `lod` through to meta2.json. `bdb` keys are sorted, so output is reproducible.
- Fails loudly if a key has no entry in `data/muscles.txt`, or a bone has no entry in `bones.py`.

### exercises.py

- `G`: macros for muscle sets (`QUADV`, `HAMS`, `ERECT`, `GRIP`, `TRI`, `OBL`, ...). Entries are `"key"` or `"key|part"`.
- `E`: list of `(name, category, equipment, cue, spec)`; `spec` = comma list of `TARGET:level`, level 3 = prime mover, 2 = synergist, 1 = stabiliser.
- `VARS`: per-exercise variation groups `{name: [(group, [(option, overrideSpec), ...])]}`. First option is the default and usually `""`. Overrides replace levels; `:0` removes a target. Part-specific overrides split a whole-muscle target into parts.
- `EQ`: maps the free-text equipment string to filter categories (Barbell, Dumbbells, Kettlebell, Cable, Machine, Bodyweight, Band, Other). A new equipment string needs an entry here or the script raises KeyError.
- Categories (must match `EXCATS` in template.html): Chest & shoulders, Back, Arms, Legs, Hinge, Full body, Core, Grip & carry, Neck.
- Current size: 148 exercises, 23 with variations, 134 muscles covered.

## META object (embedded as `const META=...`)

```js
{
  lo:[x,y,z], span:[x,y,z],                 // dequantisation
  meshes:[[kind,key,side,part], ...],        // kind "m" (muscle/tissue) or "b" (bone); same order as every geo/*.bin
  lod:{low:{file:"geo/low.bin",bytes,faces,counts:[[nv,nf],...]}, medium:{...}, high:{...}},
  db:{ key:{g:group, a:[actions], o:origin, i:insertion, n:nerve, t?:exercisesText, x?:note} },
  bdb:{ boneKey:[region, description] },
  al:{ alias:["key" | "key:part", ...] },   // data/aliases.txt
  act:[{ id, n:name, g:group, met, p:[[key,part,weight],...], s:short name, d:[defaultKind, defaultMinutes] }],   // data/activities.txt
  nd:[{ id, n:name, r:roots, k:"motor"|"mixed"|"cranial", p:parent id or "", w:[anchor,...], x:note }],   // data/nerves.txt: schematic nerve paths
  mv:[{ id, n:label, j:joint, k:[prime mover keys], s:[assisting keys], kp?:[[key,part,level 3|2],...] }],   // data/movements.txt; kp only when a part is named
  nv:{ nerveId:[muscle keys] },              // muscles each nerve supplies, derived by meta.py from db[key].n (see Nerves below)
  ex:[{ n:name, c:category, e:equipment, q:cue, t:[[key,part,level],...], v?:[[group,[[option,[[key,part,level],...]],...]]], eq:[categories] }]
}
```

Muscle groups (`MGROUPS` in template): Face, Eye, Jaw, Neck, Throat, Back, Shoulder, Chest, Abdomen, Pelvic floor, Upper arm, Forearm, Hand, Hip, Thigh, Lower leg, Foot, plus `"Connective tissue"` (tendons, fasciae, ligaments; separate layer toggle). Bone regions: Skull, Spine, Thorax, Arm, Hand, Pelvis & leg, Foot.

## Frontend architecture (tools/template.html)

Single `async` IIFE, no modules, no framework. Three.js **r128** UMD self-hosted in `vendor/three.min.js` (r128 APIs: `outputEncoding`, `sRGBEncoding`, `convertSRGBToLinear`). Fonts: Fraunces (headings, big numerals) + Source Serif 4 (reading text) + Archivo (controls, tables), self-hosted woff2 in `fonts/` via `@font-face` (no requests to Google; keep all asset URLs relative because the site is served from a sub-path). The smoke test strips the three.js `<script>` with a regex on a `src` containing `three`; keep that matching. Light/dark via CSS custom properties on `:root`.

### Look ("Anatomical atlas", v1.6)
- Palette = CSS custom properties on `:root` (light "paper"; dark "night library" under `@media (prefers-color-scheme: dark)` guarded by `:root:not([data-theme="light"])` and `:root[data-theme="dark"]`): `--bg --panel --card --ink --muted --line --accent` (oxblood) `--accent-soft --ochre --sage --plum --slate-teal --amber-warn`. `--muted` and the dark `--accent` are nudged from the design brief to reach WCAG AA (4.5:1) on every surface.
- Colours of 3D materials and their legends have ONE source: the `PAL` object in the script (theme independent: heat `h3/h2/h1`, `l0`, comparison `a2 a1 eq b1 b2`, volume `v0..v3`, `fat`, `end`), exported at start-up as `--m-<name>` custom properties; the legend classes (`.l3 .ca2 .v0 .sw.fat` ...) use `var(--m-*)`. `PALT` holds the per-theme colours (selection ochre = `--ochre`, nerves); `applyTheme()` re-colours those materials when the theme changes (matchMedia / `data-theme`). Change a colour in `PAL`/`PALT` only; `smoke.js` checks that materials, swatches and `--ochre` agree.
- Typography: `--f-disp` Fraunces (headings, big numerals), `--f-read` Source Serif 4 (card text, index entries, notes), `--f-ui` Archivo (controls, tables). Small-caps labels use `font-variant-caps:all-small-caps` + letter-spacing; section headings are numbered with CSS counters (`I · Index of structures`), Index groups with Roman numerals (`GROMAN`), cards carry a stable "Plate NNN" kicker (`PLATE`, position of the structure in the full unfiltered Index).

### Startup
1. Create renderer/scene/lights, materials.
2. Pick the quality level (`localStorage` `aom.lod.v1` if valid, else `low` on phones/coarse pointers, `medium` otherwise), `fetchLod()` the file with byte progress in `#loadMsg` ("Loading model · 2.1 MB / 4.2 MB"; `file://` and network failures write an explanatory message there and stop), `DecompressionStream('gzip')` → Uint16Array, `decodeLod()` with that level's `counts`, and build one `THREE.Mesh` per META row (`makeGeo`: `computeVertexNormals`, bounds; `DoubleSide`, `matrixAutoUpdate=false`). `allMeshes` keeps META order.
3. Index: `muscleMeshes`, `boneMeshes`, `byKey[key]`, `byBone[key]`. `mesh.userData = {kind:"muscle"|"bone", key, side, part, group, tissue}`.
4. Build UI lists, restore localStorage, `applyVisuals()`, remove loading overlay.

### Mesh quality
Segmented control `#segLod` (Low/Medium/High with sizes, `data-lod`, `data-faces`, `aria-pressed`) in the Layers popover. `setLod(level)`: fetch + decode the new file (the pressed button shows a progress fill, `aria-busy`), then swap `mesh.geometry` on every mesh in `allMeshes` (old one disposed); materials, `userData`, visibility, selection and heat mode are untouched; then `applyVisuals()`. Last request wins (`lodReq` counter + `AbortController`); a failed switch keeps the current level and writes the error into `#lodNote`. Choosing High on a phone/coarse pointer shows a large-download note. The choice is persisted only when the user picks a level.

### Camera and rendering
- Custom orbit (`orbit` current, `goal` target; theta/phi/r and the pivot tx/ty/tz) with pointer events, pinch, wheel; damped in `tick()`. Selecting a structure moves the pivot to it (`pivotOn`; paired structures use the clicked side, else the side nearer the camera via `nearSide`); `focusOn` also zooms; Reset returns the pivot to (0, 0.88, 0). `setTarget` clamps the pivot to the body box `TB`. Panning (`panBy`, screen plane): right/middle/shift-drag, two-finger drag on touch.
- Render on demand: `tick()` renders only if the camera is moving or `dirty` is set. Anything that changes visuals must go through `applyVisuals()` (sets `dirty`).
- `focusOn(kind,key)`, `faceTowards(meshes)` and `bodyZ(y)` decide front/back view and zoom.

### Material precedence in applyVisuals()
selected structure (`M_SEL`) → heat mode material (`HM` levels, `CM` comparison, `VM` volume; uninvolved = `M_GREY`) → hover (`M_HOV`) → isolate fade (`M_FADE`) → per-key base material (`keyMat`, colour jittered by hash of key). Bones: `B_SEL` / `B_HOV` / `B_FADE` / `B_MAT`. Picking (`pick()`, Raycaster) ignores meshes whose material is in `FADED` or has opacity ≤ 0.15. All material colours are converted with `convertSRGBToLinear`.

### Exercise logic
- `effTargets(i, vars)`: base targets with variation overrides applied.
- `perOf(targets)` → `{per:{key:{l,parts}}, tot}`; weights `W = {3:1, 2:0.45, 1:0.15}`. Specificity of a muscle = `W[level] / tot`.
- `EXK[key]`: precomputed ranking per muscle, entries `{i, v, l, parts, s}`. `v` is null for the base exercise; otherwise the option-index array of ONE non-default option (other groups default), added only when that variation beats the base for that muscle (higher level, higher rounded specificity, or a visible part emphasis; equal/worse variants are skipped, combinations across groups are not enumerated). Shown as `exLabel(x)` = "Back squat (Wide)"; rows carry `data-ex` + `data-v`, and `openEx()` sets `exVars[i]=v` (empty = defaults) before `selectEx(i)`. Used by "Best exercises for" and the muscle card table.
- `meshLevels(targets)`: Map mesh → level, respecting part-specific targets.
- Volume: `VOLF = {3:1, 2:0.5, 1:0}` sets per weekly set; `volumeByMesh()`, `volOfKey(key, part)`; bands are relative to the goal range `tg={g,lo,hi}` (presets Maintain 4–6, Strength 6–10, Muscle close to failure 8–12 (default), Muscle moderate 10–20, or Custom 1..40): 0 Low (<lo/2), 1 Below target, 2 In target, 3 More than needed (`volBand`, `volStatus`, classes `v0..v3`, `VM`). `renderSuggest()`/`suggestions()`/`sugScore()` is the gap filler: greedy top 3 default-variation exercises (3 sets each, equipment-filtered, not in the plan, rescored after each pick) over the `SUMMARY` groups (exact: per-mesh volume plus the candidate's per-mesh contribution `sugAdd()`, max over group members). Score: per group, gain = w·(U(n)−U(s)) with U(x)=x−x²/(2·lo), x capped at `lo` (a set is worth w·(1−s/lo): the first sets into an empty group count most, nothing past `lo`); w is the row's third element (1, or .33 for 15 minor rows such as front delts, upper traps, rhomboids, rotator cuff, forearms, abs, obliques, lower back, glute medius, hip flexors, adductors, soleus, tibialis). Group gains are sorted and credited 1, 1/2, 1/4, ... (so a broad compound cannot win on many small spills; the exercise whose prime movers are the biggest gaps wins), then multiplied by (1 − waste/sets added to SUMMARY groups), waste = `SPILL` (0.5) per set landing in a group already at `lo` (up to `hi`) + `OVER` (1) per set above `hi` (relative, so it never flips the sign and the 1-set target still converges), and by `FULLF` (0.6) for category "Full body" (technical, fatiguing lifts). The listed "+N" per group is the useful part (sets toward `lo`, capped at the gap), top 3 groups by weighted gain. Scenario check (squat + bench → a row, a hamstring exercise, a delt exercise; PPL without calves → calf raise) lives in smoke.js; known data-driven quirk: exercises with generous target lists (Meadows row: rear delt 3; Cuban press: side delt 3) tend to win their slot over staples (Barbell row, Face pull, Lateral raise). `SUMMARY` lists the 27 rows of the weekly table; a row is `[label, "key[|part],key[|part],...", weight?]` (weight only used by the gap filler) and shows the MAX weekly sets over its members (e.g. Quadriceps = four heads; Hip flexors = psoas major + iliacus, rectus femoris deliberately omitted). Clicking a row selects its first key.

### Layout, bottom sheet and touch
- `#toolbar` floats on `#vp`: a Layers popover (`#btnLayers`/`#popLayers`: toggles + opacity sliders) and the view buttons (`#popView`; inline on desktop, a View popover on phones). Popovers: `aria-expanded` on the button, `.open` on the popover, one at a time (`POPS`, `closePops()`), closed by outside click and Escape.
- Phone = `matchMedia("(max-width:760px)")` (`isPhone()`; guarded for absence). `<aside id="side">` becomes a bottom sheet with `data-sheet="peek|half|full"` (`setSheet()`, heights from CSS vars/`sheetH()`); the header `#shead` (handle `#grab` + title + tabs) drags with pointer events (velocity-aware snap) and the handle tap cycles states. `#sbody` scrolls inside the sheet.
- On phones `#card` is moved into `#cslot` (back into `#vp` on desktop, `placeCard()`); while shown the sheet has `has-card` and hides the panes. Tapping a tab sets `cardAway` and collapses the card to a `.mini` summary. `select()`/`selectEx()` call `revealCard()` (opens peek to half). `renderCard()` is a wrapper that calls `syncCardUI()` after `renderCard0()`.
- `applyInset()` (ResizeObserver on the sheet) sets `camera.setViewOffset` so the body is centred in the uncovered area; `baseRadius()` divides by `visFrac(sheetNom)` and `setSheet()` rescales `goal.r`. Picking is unaffected (NDC from the full canvas rect). Pixel ratio capped at 1.5 on phones.
- Touch: tap shows `#tip` for 1.5 s (`showTipAt`), drag threshold 10 px for touch (5 for mouse), double-tap on the selected structure = `focusOn`. `@media (pointer:coarse)` enlarges hit areas to 44 px; search inputs are 16 px.

### Cards and lists
`renderCard()` dispatches to `renderCmpCard()`, `renderExCard()` or the muscle/bone card. Click handling is delegated on `#card` via `data-act`, `data-ex`, `data-key`, `data-var`. Sidebar tabs: Anatomy (`buildList` with per-structure checkboxes and an eye button `.geye` on every group heading; `data-gk` m = muscle group (`state.groups`), t = connective tissue (`state.tendons`), b = bone group (`state.bgroups`), n = nerves layer; `aria-pressed` true/false/"mixed" when the group is shown but some items are hidden one by one; `syncGroups()` refreshes them from `syncList()`; "Show all" / "Hide all" links next to "Show hidden"), Exercises (`buildEq`, `buildBest`, `buildExList`, comparison banner), Workout (`renderPlan`, `buildAdd`, `renderVolSum`, `#tVol`).

### Training days, week overview and recovery model

### Search (`ALIAS`, `aliasHits`, `exSearch`, `fuzzyHay`, `near`)
Index (`#q`), exercise (`#qe`) and planner-add (`#qa`) searches first do the old substring match, plus alias matches (the query equals or starts an alias such as "lats", "hammies", "rear delts"). Exercises match an alias when a base target hits the aliased key (and its part, for part aliases such as `deltoid:spinal part`). Only if nothing matches and the query has >= 4 characters, a typo fallback compares each query word with name words and alias words (edit distance incl. transposition, <= 1 edit, <= 2 for words of 8+ characters).

### Nerves (schematic peripheral nerves)
- The source data has no nerve meshes. `tools/data/nerves.txt`: `id|name|roots|kind|parent id or -|waypoints|note|match` (8 fields, one nerve per line, parents before children; defined for the subject's LEFT side and mirrored for the right). `waypoints` (`;`-separated anchors, resolved at runtime against the loaded meshes, so they follow the bones and muscles at every quality level): `xyz:x,y,z`; `spine:C5[:dx,dy,dz]` (a point beside that vertebra; S1-S4 are placed below L5 because the sacrum is missing); `bone|muscle:key:fx,fy,fz[:dx,dy,dz]` (fractions of the bounding box of that structure on that side) or `bone|muscle:key:sT[:dx,dy,dz]` (centre of the vertices in a slab at fraction T of the height measured from the top: follows a limb bone's axis). Offsets are metres in the left-side frame (+x lateral for the left limb, +y up, +z front). Unsided structures (vertebrae, diaphragm) are mirrored for the right side.
- `match`: `;`-separated lower-case substrings looked up in each muscle's nerve text (`db[key].n`); `-` marks a trunk/plexus whose muscles come through its branches. `meta.py load_nerves()` writes `META.nd`/`META.nv`; a muscle that also matches a descendant of a nerve is listed only under the descendant (most specific wins). `lint.py` checks syntax, parents, that anchors reference existing muscles/bones, that every non-trunk nerve supplies at least one muscle and every trunk has a supplying branch, and prints (info, not failure) muscles whose nerve text matched no nerve. Current: 53 nerves, all 176 muscles covered.
- `template.html` ("nerves" section before `applyVisuals`): `buildNerves()` makes one merged mesh per nerve and side (`userData {kind:"nerve", key:id, side}`, a `THREE.TubeGeometry` along a `CatmullRomCurve3` trunk, 3 mm radius for top-level nerves, 2.2 mm for branches, 2 mm cranial, plus 1.4 mm bezier tubes from the nearest trunk (or ancestor) point to the centre of each supplied muscle) and an invisible fatter twin (`nerveHits`, 2.6x radius) used for picking. `effSide()` takes the side from the mesh position because the source labels one mesh pair (flexor pollicis brevis) with the wrong side. Built lazily on the first switch-on (`setNerves(true)`), rebuilt by `setLod()` (anchors depend on bounding boxes) or discarded when the layer is off.
- Layer toggle `#tNerves` (default off, stored in localStorage `aom.nerves.v1` as true/false). Switching on with opaque muscles sets muscle opacity to 45% (`nvAuto`), switching off restores 100% unless the slider was touched meanwhile. `pick()` returns a nerve behind translucent muscles (opaque bones/muscles in front still block). Selecting a nerve (`select("nerve", id)`, also switches the layer on) lights its muscles with `M_SEL` (muscles reached only via branches `M_SEL2`) and the nerve with `N_SEL`; selecting a muscle highlights its nerves (`N_REL`). The nerve card lists roots, parent, branches, supplied muscle chips (`data-key`), note; the muscle card's Nerve field links to its nerves (`data-nerve`). Index has a "Nerves (schematic)" group. Deep link `#n=<id>`.

### Persistence
localStorage, all wrapped in try/catch. `aom.nerves.v1`: `true|false`, the Nerves layer (see Nerves). `aom.lod.v1`: `"low"|"medium"|"high"` (written only on an explicit choice; anything else is ignored). `aom.plan.v3`: `{days:[{name, items:[{n:exerciseName, sets, v:[optionName per variation group]}]}]}` (seven days, missing days are padded; names trimmed to 16 characters, empty = "Day N"; `""` or missing option = default option; unknown names fall back to the default, entries for exercises that no longer exist are dropped). Migration: if v3 is absent, `aom.plan.v2` (a flat `[{n,sets,v}]` list) or the legacy `myology.plan.v1` is loaded into Day 1, v3 is written and the old keys are removed. `aom.lic.v1`: the licence key string (raw, not JSON; stored only after it verified; part of the JSON backup; see Licence / Pro). `aom.ovview.v1`: overview view `"sch"` (default) or `"mus"`. `aom.log.v1`: training log, see Training log below. `aom.eq.v1`: array of enabled equipment categories. `aom.goal.v1`: `{g:"maintain"|"strength"|"hyp8"|"hyp10"|"custom",lo,hi}` (written on change only; presets take lo/hi from `GOALS`, invalid custom ranges fall back to the default). In memory `week[].items[].v` and `exVars` are option-index arrays; conversion happens only in `loadPlan()`/`savePlan()` (`varNames`/`varIdx`), so reordering `VARS` options is safe but renaming one resets it to the default. Legacy keys `myology.plan.v1` (variation indices, validated against the current `EX[i].v`) and `myology.eq.v1` are migrated on first load and then removed. Bump the version suffix if the format changes.

Service worker: `geo()` registers its cache write with a synchronous `waitUntil` (Safari rejects late calls); requests with `&direct=1` bypass the worker. `fetchLod` retries once with `&direct=1` when a controlled fetch fails, so a broken worker cannot block loading or the quality switch.

Version display: `#ver` in the viewport corner (bottom right; top right on phones) shows `v<tools/version.txt> · <build id>`; the build id is an md5 of template + META + version computed in `assemble.py`. **Bump `tools/version.txt` (1.0 → 1.1 …) with every user-visible release.** Current: 1.11 (1.11 licence-key groundwork for Pro, nothing gated; 1.10 Save image as a toolbar button; 1.8 training-day tracking + backup/PNG export, 1.9 movement search; 1.3 schedule board, 1.4 schematic nerves, 1.5 toolbar Volume button, 1.6 anatomical-atlas redesign, 1.7 index group eye toggles).

### Endurance, heart-rate zones and week balance (v1.2)
- Session `{a:activityId, k:kind, min, n, len, rec, sp}` (`mkSes` fills/clamps; `cleanSes` validates on load). Kinds: `easy` (all Z2), `long` (10% Z1, 90% Z2), `tempo` (`len` = work minutes, 40% Z3 / 60% Z4, rest Z2), `vo2` (`n` x `len` Z5, `rec` Z2, default 4 x 4 / 3 min in 40 min), `hiit` (`n` x `len` Z5 with 0.5 min steps, default 8 x 30 s, `rec` 1.5 min split Z1/Z2), `rounds` (combat only: `n` pad/bag rounds of `len` minutes, half Z4 half Z5, `sp` sparring rounds Z5, `rec` rest Z2 between rounds, the remaining minutes are technique, 70% Z2 / 30% Z3). `sesSegs(s)` returns labelled zone-minute segments; everything else (`sesZ`, pills, rows, balance, load) derives from it. The activity default kind/minutes come from activities.txt (combat: rounds 60/90).
- On disk the sessions live in the same `items` list as the exercises, as `{t:"e", ...session}` (strength entries have no `t`), so v1.1 plans load unchanged and a v1.1 reader simply drops them. In memory they are split into `week[d].items` and `week[d].ses`; `dayOut()` writes, `loadWeek()` reads.
- Load model: `sesRaw(s)` = sum(zone minutes x `CZ` = [.008,.022,.045,.09,.15]) and group load = raw x the activity's weight for the SUMMARY group (`actW`, max over profile entries touching the group's members) = set equivalents. Calibration: easy run 45 min = 1.0 for quads and calves, VO2max 4x4 run = 2.9, Muay Thai 90 min with 8x3 pad rounds = 3.1 for delts/hip flexors/calves (weight .65) and ~2.1 for weight .45 muscles. `dayModel()` adds `N` (endurance) to `E` (strength) as `T`; `T` drives carry-over `F` and conflicts `C` (a group counts as trained at T >= 1.5), while the weekly table, goal bands (`M.W`), `volOfKey` and the gap filler's fill logic use strength only; the gap filler's day placement (`bestDay`, `confCount`) works on `T`. Conflicts are warnings only (day card, row note, overview).
- Heart rate: `aom.hr.v1` `{max, age, rest}` (nulls when unset; max 100-230, age 10-100, resting 30-120). `hrMax()` = entered max, else round(208 - 0.7 x age); `bpmAt(p)` = p x max, or Karvonen rest + p x (max - rest) when resting HR is set (and < max - 20); zone bounds `ZP` = 50/60/70/80/90/100 %. Text via `zoneTxt`/`segTxt`: "Z5 · 171–190 bpm", or "Z2 · 60–70 % HRmax" without a max.
- UI: day cards `#wstrip` (horizontal scroller with snap, 84 px cards: name, strength pill "N sets", one coloured pill per session `pillOf`/`pillCls` (easy/long teal `pe`, tempo amber `pt`, vo2/hiit/rounds red `ph`), strength load bar, dashed `.rest`, ⚠ for conflicts); session rows `#ses` (activity + kind selects, minutes input, "Edit intervals/rounds/work" expands `.sdet` number inputs, Move to…, zone lines with bpm, ⚠ notes); `#endOpen` opens `#endForm` (activity, type, minutes, "Add to Day N"); `<details id="hrSet">` heart-rate settings and zone table; `#bal` week balance (`balance()`/`balHtml()`: strength sets and groups in target, endurance equivalent minutes Z2+Z3+2x(Z4+Z5) vs WHO 150-300, easy (Z1-2) / moderate (Z3) / hard (Z4-5) split vs >= 75% easy, VO2max-like sessions (vo2, hiit, or rounds with >= 12 min in Z4-5) vs 1-2, minutes per zone); the same cards at the top of the overview (`#ovBal`, inside the scroller) plus an Endurance row (`tr.er .eb`: minutes and zone mix per day) and a teal strip (`.ef`) in muscle cells that carry endurance load. 3D: the volume heatmap "Selected day" paints endurance-loaded muscles (profile weight x raw load >= 0.4) teal (`M_END`), strength colours first, then teal, then the amber recovery material.

## Licence / Pro (groundwork, v1.11; nothing is gated yet)

- Full description, threat model and procedures: `docs/licensing.md`. Key = `AOM1-<b64url payload JSON>.<b64url 64-byte ECDSA P-256/SHA-256 signature (IEEE P1363 r||s) over the ASCII "AOM1." + b64url payload>`; payload `{v:1, id (10 chars A-Z2-7), tier:"pro", iat, exp?, name?}` (name <= 40 chars, no other personal data). Whitespace in a pasted key is ignored.

- `template.html` ("licence" section before `#foot`): `LICPUB`/`LICREV` (build-time constants), `parseKey`, `verifyKey(str)` -> `{ok,payload}|{ok:false,reason}` with reasons `format|signature|expired|revoked|unsupported` (no `crypto.subtle`: insecure http), `isPro()` (sync, from `licState`, the last result), `FEATURES = {name:{pro,label}}` + `hasFeature(name)` (3 placeholder entries, all `pro:false`: gate a feature by flipping its flag and calling `hasFeature`). `licStartup()` re-verifies the stored key silently; a key that no longer verifies stays stored but is not Pro and the panel shows the reason. `exp` is inclusive and compared with the device's local date.
- UI: `<details id="lic">` "Pro & licence" in the colophon (`.foot`): `#licStatus` ("Free version" / "Pro active · licensed to <name> · since <iat>[ · until <exp>]" / "Free version. <reason>"), `#licMsg` (failed attempt; never changes the current status), `#licKey` textarea, `#licAct`, `#licDel`, `#licBadge`; `data-pro="1|0"` on `#lic` and `<html>`. All payload text goes through `esc()`.
- Tests: `licenseRun()` in smoke.js uses a throw-away TEST key pair made by the CLI, swaps `LICPUB`/`LICREV` in the script text (`opts.js` of `boot()`), exposes internals through the `//@licexport` marker line (a harmless comment in production) and gives the jsdom window Node's `webcrypto` (`opts.nosubtle` removes it). ## Known limitations and open issues

- Exercise involvement uses three coarse levels estimated from EMG literature and coaching practice; specificity and volume inherit that coarseness.
- `EXK` ranks single non-default variation options only (not combinations across groups, e.g. Wide + Deep squat), and a part emphasis is shown only when it is the top level for that muscle.
- Left and right share one key: hiding, exercise heat and volume always apply to both sides; single-sided exercises light both legs.
- Missing structures in source data: tongue, pharyngeal constrictors, buccinator, auricular/occipitalis, perineal muscles, extensor digitorum brevis, dorsal interossei of the foot; sacrum, coccyx, costal cartilages.
- Anatomy and exercise texts were written for this project and are not reviewed by an anatomist; innervation of small hand/foot/laryngeal muscles is the most error-prone.
- Plan and training log live in localStorage only; the user can back them up with "Export data" (JSON, all `aom.*` keys) and restore with "Import data".
- Endurance load is a coarse zone-minute estimate (per-activity profile weights are coach-level guesses, not measured); muscles outside the 27 SUMMARY groups (serratus anterior, neck, ...) only show on the 3D heatmap, not in the fatigue grid.
- The fatigue / recovery model is a deliberately crude estimate (fixed carry-over weights, no intensity, no individual recovery). A group's value per day is the max over its meshes, so the Week column can be lower than the sum of the day cells for groups whose members are trained on different days.

## Offline / PWA

- `sw.js` is generated by `assemble.py` from `tools/sw.template.js`. Precache = `SHELL_FILES` in `assemble.py` (index.html, manifest, vendor/three.min.js, icons, fonts). Add any new shell asset to that list, or it is not available offline. Cache names: `aom-shell-<build hash>` (changes with any shell file) and `aom-geo-<geo hash>` (changes only when a `geo/*.bin` changes). Activate deletes other `aom-*` caches.
- Strategies: navigations network-first (`cache: no-cache`, 5 s timeout, falls back to the cached `index.html`); `geo/*.bin` cache-first, stored on first use only (High is 9.9 MB, so levels are never precached); other same-origin GETs cache-first from the shell cache. `skipWaiting` + `clients.claim` so a new version takes over at once.
- Registration: a tiny inline script at the end of `template.html`, only on http(s) and when `navigator.serviceWorker` exists (so not on `file:` and not in jsdom). All URLs are relative; scope is the directory of `sw.js`.
- Dev note: on localhost the SW also registers; use DevTools > Application > "Update on reload" or unregister it if a stale shell confuses you.
